📦 Gestão de Projetos com Maven

Automação de Build e Dependências

Módulo 1 – Introdução

1. O que é o Apache Maven?

O Maven é uma ferramenta de automação de compilação (build) e gerenciamento de dependências para projetos Java. Ele utiliza o conceito de Project Object Model (POM) para descrever a estrutura do projeto.

Principais objetivos:

  • Facilitar o processo de build.
  • Prover um sistema de build uniforme.
  • Gerenciar bibliotecas externas automaticamente.

2. O Coração do Projeto: POM.xml

O pom.xml é o arquivo XML que contém informações sobre o projeto e detalhes de configuração usados pelo Maven para compilar o código.

<project>
  <groupId>com.meuexemplo</groupId>
  <artifactId>meu-app</artifactId>
  <version>1.0-SNAPSHOT</version>
</project>

3. Ciclo de Vida do Build

O Maven baseia-se no conceito central de ciclos de vida. Os comandos principais são:

mvn compile
Compila o código fonte.
mvn test
Executa testes unitários.
mvn package
Cria o JAR/WAR.
mvn clean
Remove a pasta target.
Módulo 2 – Dependências e Repositórios

4. Gerenciamento de Dependências

Em vez de baixar JARs manualmente e colocá-los no classpath, você apenas declara a dependência no POM e o Maven a busca no Maven Central Repository.

<dependency>
  <groupId>org.mongodb</groupId>
  <artifactId>mongodb-driver-sync</artifactId>
  <version>4.11.1</version>
</dependency>

5. Repositório Local vs Remoto

  • Local (~/.m2): Pasta no seu computador onde o Maven armazena os downloads para não precisar baixar novamente.
  • Remoto: Servidores na web (como o Maven Central) de onde as bibliotecas são baixadas.

6. Estrutura de Diretórios Padrão

O Maven dita onde cada arquivo deve estar ("Convention over Configuration"):

meu-projeto/
├── src/
│ ├── main/java/ (Código fonte)
│ └── test/java/ (Testes unitários)
├── target/ (Arquivos gerados)
└── pom.xml (Configuração)
