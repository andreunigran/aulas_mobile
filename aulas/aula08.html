Guia de Bancos de Dados em Flutter

Armazenamento e Gerenciamento de Dados em Aplicações Flutter.

O que é um Banco de Dados?

Um banco de dados é um conjunto organizado de informações armazenadas e acessadas eletronicamente. Sua principal função é permitir o armazenamento, a manipulação e a recuperação de dados de forma eficiente.

Por que Usar um Banco de Dados em Flutter?

  • Persistência de Dados: Manter dados salvos mesmo quando o aplicativo é fechado.
  • Estruturas Complexas: Gerenciar relacionamentos complexos entre diferentes tipos de dados.
  • Performance: Acesso rápido e eficiente a grandes volumes de informações.

Tipos de Bancos de Dados

Relacionais (SQL)

Organizam os dados em tabelas com linhas e colunas, seguindo um esquema rígido. Utilizam a linguagem SQL para consultas. São ideais para dados estruturados e relacionamentos bem definidos.

Exemplo: SQLite.

Não Relacionais (NoSQL)

Armazenam dados em formatos flexíveis, como documentos (JSON), grafos ou chave-valor. São ótimos para dados não estruturados e aplicações que precisam de alta escalabilidade.

Exemplo: Firebase Firestore.

SQLite em Flutter

O que é SQLite?

É um banco de dados leve e embutido no próprio aplicativo, ideal para dispositivos móveis. Ele não requer um servidor separado e armazena todos os dados em um único arquivo no dispositivo.

Vantagens

  • Simplicidade e baixo consumo de recursos.
  • Suporte a transações ACID (Atomicidade, Consistência, Isolamento e Durabilidade), garantindo a integridade dos dados.
  • Ótima performance para operações locais.

Configurando o SQLite

Para usar o SQLite no Flutter, você precisa adicionar as dependências `sqflite` e `path` no seu arquivo `pubspec.yaml`.

# pubspec.yaml
dependencies:
  sqflite: ^2.3.0 # Verifique a versão mais recente no pub.dev
  path: ^1.8.3

Depois, execute `flutter pub get` no terminal ou `flutter pub add sqflite` e `flutter pub add path`.

Programação Assíncrona

Por que Assíncrono?

Operações de banco de dados (ler ou gravar em disco) podem ser lentas. Se fossem síncronas, elas travariam a interface do usuário (UI), resultando em uma péssima experiência. A programação assíncrona permite que essas operações ocorram em segundo plano, mantendo o app responsivo.

`Future`

Um `Future` é um objeto que representa uma operação assíncrona e seu resultado eventual. Pense nele como uma "promessa" de que você receberá um valor (ou um erro) no futuro. Ele pode estar em três estados: não concluído, concluído com sucesso (com um valor) ou concluído com erro.

`async`

A palavra-chave `async` é usada para marcar uma função como assíncrona. Isso significa que a função pode conter operações que retornam um `Future`, permitindo o uso de `await` dentro dela.

  • Retorno de um Future: Uma função `async` sempre retorna um `Future`. Se você retornar um valor (ex: `String`), ele será encapsulado em um `Future`.
  • Uso de Await: Permite o uso da palavra-chave `await` dentro do seu corpo.

`await`

O `await` pausa a execução da função `async` até que o `Future` seja concluído. Isso permite escrever código assíncrono que parece síncrono, tornando-o muito mais fácil de ler.

  • Esperar o Resultado: Em vez de usar callbacks (`.then()`), você simplesmente "espera" pelo resultado.
  • Uso Obrigatório em Funções `async`: `await` só pode ser usado dentro de funções marcadas com `async`.

Tratamento de Erros

Se um `Future` que você está aguardando (`await`) falhar, ele lançará uma exceção. Para lidar com isso de forma segura e evitar que seu aplicativo quebre, você deve envolver a chamada `await` em um bloco `try-catch`.

Future<void> carregarDados() async {
  try {
    final dados = await buscarDadosDoServidor();
    print('Dados carregados: $dados');
  } catch (e) {
    print('Ocorreu um erro: $e');
  }
}

Operações CRUD com SQLite

Inicializando o Banco

Antes de realizar qualquer operação, precisamos abrir o banco de dados e criar as tabelas, caso elas não existam.

import 'package:sqflite/sqflite.dart';
import 'package:path/path.dart';

Future<Database> initializeDB() async {
  String path = join(await getDatabasesPath(), 'meu_banco.db');
  
  return await openDatabase(
    path,
    onCreate: (db, version) {
      return db.execute(
        "CREATE TABLE usuarios(id INTEGER PRIMARY KEY, nome TEXT, idade INTEGER)",
      );
    },
    version: 1,
  );
}

CRUD (Create, Read, Update, Delete)

Estas são as quatro operações básicas de persistência de dados.

// Create: Inserir um novo usuário
Future<void> inserirUsuario(Usuario usuario) async {
  final Database db = await initializeDB();
  await db.insert('usuarios', usuario.toMap(), conflictAlgorithm: ConflictAlgorithm.replace);
}

// Read: Obter todos os usuários
Future<List<Usuario>> obterUsuarios() async {
  final Database db = await initializeDB();
  final List<Map<String, dynamic>> maps = await db.query('usuarios');
  
  return List.generate(maps.length, (i) {
    return Usuario.fromMap(maps[i]);
  });
}

Modelando Entidades

O que é uma Entidade?

Uma entidade é uma classe Dart que representa uma tabela do banco de dados. Ela serve como um "molde" para os objetos que serão salvos e recuperados, facilitando a conversão entre o mundo dos objetos Dart e o mundo das tabelas SQL.

Recursos Úteis: `Map` e `factory`

`Map`

`Map` é uma coleção de pares chave-valor (ex: `'nome': 'Ana'`). É o formato que a biblioteca `sqflite` usa para se comunicar com o banco. Para inserir dados, você converte seu objeto para um `Map`. Para ler dados, o `sqflite` te devolve um `Map`, que você então converte de volta para seu objeto.

Construtor `factory`

Um construtor `factory` é um tipo especial de construtor que não cria, necessariamente, uma nova instância da classe. Ele é ideal para cenários de conversão, como criar um objeto a partir de um `Map`. O padrão `fromMap` é uma convenção comum para essa finalidade.

class Usuario {
  final int id;
  final String nome;
  final int idade;

  Usuario({required this.id, required this.nome, required this.idade});

  // Método para converter um Usuario em um Map (para salvar no BD)
  Map<String, dynamic> toMap() {
    return {
      'id': id,
      'nome': nome,
      'idade': idade,
    };
  }
  
  // Construtor de fábrica para criar um Usuario a partir de um Map (vindo do BD)
  factory Usuario.fromMap(Map<String, dynamic> map) {
    return Usuario(
      id: map['id'],
      nome: map['nome'],
      idade: map['idade'],
    );
  }
}
